- (event) Nova rodada de arquitetura iniciada para substituir a stack anterior por PHP/Laravel no backend, Next.js no frontend/BFF e PostgreSQL como banco recomendado.
- (decision by user) Backend será PHP + Laravel.
- (decision by user) Frontend será Next.js.
- (decision by user) A arquitetura deve incluir BFF.
- (decision by user) A implementação deve seguir SOLID, Domain Pattern e testes de CI/CD.
- (decision) PostgreSQL escolhido como banco principal por consistência transacional, JSON/briefings, auditoria, relatórios e maturidade para pedidos complexos. Binds: pedidos, pagamentos, briefing, arquivos, auditoria, métricas. Prevents: limitação de consulta/consistência em fluxos operacionais complexos.
- (version) Verificado em fontes oficiais em 2026-07-27: PHP 8.5.x estável, Laravel 13.x, Next.js 16.2.x, React 19.2.x, PostgreSQL 18.x, Laravel Testing/Pest/PHPUnit, Laravel Queues, Laravel Sanctum, GitHub Actions.
- (decision) Paradigma atualizado: frontend Next.js com BFF + backend Laravel API orientado a domínio + PostgreSQL transacional. Binds: storefront, customer-area, admin, checkout, pedidos, briefing, produção, suporte. Prevents: UI acoplada à API interna e regras de negócio espalhadas entre frontend e backend.
- (decision) Next.js BFF será a borda de experiência: SSR/SEO, composição de dados para tela, sessão/cookies, proxy seguro e adaptação de payloads. Não contém regra de negócio principal. Binds: UI, SEO, Área da Cliente, admin web. Prevents: duplicação de domínio e exposição direta de contratos internos ao navegador.
- (decision) Laravel API será o dono do domínio e das regras comerciais: pedidos, carrinho persistido, preço, pagamento, briefing, aprovação, produção, entrega, fatura, suporte, autorização e auditoria. Binds: todos os fluxos transacionais. Prevents: divergência de regra entre BFF, jobs, admin e webhooks.
- (decision) Backend organizado por módulos de domínio com camadas Application, Domain, Infrastructure e Interfaces/Http. Binds: SOLID, Domain Pattern, testes. Prevents: controllers gordos, Eloquent como domínio e acoplamento a provedores.
- (decision by user) Eloquent está incluso como ORM do Laravel, mas restrito à camada Infrastructure/persistência. Binds: backend Laravel, repositories, queries, migrations. Prevents: Models Eloquent virarem entidades de domínio ou concentrarem regra de negócio.
- (decision) API Laravel expõe REST JSON versionado inicialmente em `/api/v1`; contratos estáveis devem ser documentáveis por OpenAPI quando a implementação iniciar. Binds: BFF, integrações, testes. Prevents: contratos implícitos quebrando front/backend.
- (decision) Autenticação cliente/admin usa Laravel como autoridade; Next.js BFF mantém sessão/cookies e nunca expõe tokens sensíveis ao navegador. Binds: checkout guest, Área da Cliente, admin. Prevents: tokens espalhados no frontend e acesso indevido a pedidos.
- (decision) Filas e trabalhos assíncronos pertencem ao Laravel; Redis é seed para cache/fila e Horizon é candidato para monitoramento operacional. Binds: notificações, webhooks, uploads, entrega digital, fatura, rastreio. Prevents: efeitos colaterais bloqueando requisições web.
- (decision) CI/CD deve testar backend, frontend e e2e em pull request antes de merge/deploy. Binds: qualidade, segurança, regressão. Prevents: implementação sem verificação automatizada.
- (question) Confirmar hospedagem final para frontend, API, banco, Redis, storage privado e workers.
- (question) Confirmar estratégia exata de autenticação entre Next.js BFF e Laravel: Sanctum SPA, sessão compartilhada por domínio, ou token server-to-server protegido no BFF.
- (question) Confirmar provedor de storage privado, pagamentos, fatura, e-mail, WhatsApp e transportadora.
- (event) Spine Laravel+BFF será criado como contrato técnico atual para regenerar épicos/stories.
